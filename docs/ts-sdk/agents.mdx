## Overview

There are two HyperCLI-related namespaces in the TS SDK:

- `client.agent`
- `client.deployments`

`client.agent` covers account metadata.
`client.deployments` covers live runtime containers.

## URL Model

The TS SDK splits the product API and agents API cleanly:

- `apiUrl`
  - main HyperCLI REST API
- `agentsApiBaseUrl`
  - HyperCLI deployments REST API
- `agentsWsUrl`
  - HyperCLI backend WS base for shell/logs
- `client.agent.baseUrl`
  - inference base derived from `agentsApiBaseUrl` by replacing `/api` with `/v1`

Recommended defaults:

```bash
HYPER_API_BASE=https://api.hypercli.com
AGENTS_API_BASE_URL=https://api.hypercli.com/agents
AGENTS_WS_URL=wss://api.agents.hypercli.com/ws
```

## `client.agent`

Use this namespace for:

- `plans()`
- `subscriptions()`
- `subscriptionSummary()`
- `entitlements()`
- `purchaseEntitlementFromBalance(planId, { duration, tags? })`
- `redeemGrantCode(code)`
- `updateSubscription(subscriptionId, { planId, quantity })`
- `cancelSubscription(subscriptionId)`
- `createStripeTrialCheckout({ successUrl?, cancelUrl? })`
- `models()`
- `discoveryHealth()`
- `discoveryConfig()`

The key split is:

- `entitlements()`
  effective current account state, including pooled inference, slot inventory, active entitlement count, and `billingResetAt`
- `subscriptions()`
  recurring card-backed billing objects such as Stripe subscriptions, including `cancelAtPeriodEnd`
- `subscriptionSummary()`
  combined account view that includes the effective `entitlements` object,
  concrete grants in `entitlementItems`, and the active subscription list
- `updateSubscription()`
  unified recurring billing mutation surface for upgrade, downgrade, and cancel-at-period-end

Example:

```ts
const summary = await client.agent.subscriptionSummary();
const entitlements = await client.agent.entitlements();
const entitlementItems = summary.entitlementItems;
const subscriptions = await client.agent.subscriptions();

const trialCheckout = await client.agent.createStripeTrialCheckout({
  successUrl: "https://agents.hypercli.com/dashboard/agents?checkout=success&session_id={CHECKOUT_SESSION_ID}",
  cancelUrl: "https://agents.hypercli.com/dashboard/agents?checkout=cancelled",
});
window.location.assign(trialCheckout.checkoutUrl);

await client.agent.purchaseEntitlementFromBalance("solo", {
  duration: 30 * 24 * 60 * 60,
  tags: ["customer=acme"],
});

await client.agent.redeemGrantCode("7f7d2f3a-1c4f-4d4d-8bdb-66a0df3d6f59");

await client.agent.updateSubscription("sub_123", { planId: "team", quantity: 1 });
```

Subscription updates select one canonical plan and a positive quantity. Use
the dedicated method to cancel at period end:

```ts
await client.agent.cancelSubscription("sub_123");
```

## Grants And Balance Purchases

Two account-level helpers now mint entitlements without going through Stripe:

- `purchaseEntitlementFromBalance(planId, { duration, tags?, extendExisting? })`
  - charges Orchestra balance
  - creates a `grant`
  - creates a new entitlement unless `extendExisting: true` is explicit
- `redeemGrantCode(code, { extendExisting? })`
  - applies an existing unapplied grant by code, creating a new entitlement unless the code or request explicitly extends

`duration` is always in seconds.

Grant redemption stacks by default: repeated codes can create parallel active entitlement windows and add slots. Use `extendExisting: true` only when the intent is to renew the latest matching `planId + tags` entitlement.

## `client.deployments`

Use this namespace for:

- create / start / stop / delete
- slot inventory / metrics
- files
- exec
- backend WS logs and shells
- OpenClaw gateway access

`budget()` now returns:

- `slots`
  exact-tier granted / used / available counts
- `pooled_tpd`
  additive inference across active entitlements
- `size_presets`
  runtime CPU / memory shapes for each tier

For account-facing billing and capacity screens, prefer `client.agent.entitlements()` or `client.agent.subscriptionSummary()` over `budget()`. `budget()` is runtime deployment capacity data, not recurring billing state.

## Create

```ts
const agent = await client.deployments.create({
  name: "docs-demo",
  size: "medium",
  start: true,
  env: { APP_ENV: "prod" },
});
```

Omitting `size` selects `small`. Choose `medium` or `large` explicitly only
when the account has a compatible free slot.

Routes can also be reconciled without restarting the deployment. `setRoutes`
replaces the complete declarative map; `setRoute` and `removeRoute` mutate one
name atomically:

```ts
let state = await client.deployments.getRoutes(agent.id);

state = await client.deployments.setRoute(
  agent.id,
  "app",
  { prefix: "app", port: 8080, auth: true },
);

state = await client.deployments.setRoutes(
  agent.id,
  {
    app: { prefix: "app", port: 8080, auth: true },
    public: { prefix: "", port: 3000, auth: false },
  },
);

await client.deployments.removeRoute(agent.id, "app");
```

Desired `routes` remain separate from `routeStatuses`, which holds resolved
URLs and live infrastructure status. Therefore a
`getRoutes()`/`setRoutes(state.routes)` round trip is lossless. At most ten
routes are allowed.

Managed runtimes can pass the reserved target `self` to `get`, `start`, `stop`,
and route methods. The backend authorizes that narrow whitelist from the active
runtime-key binding while the generic runtime scope remains `agents:none`.
`start("self")` sends an empty body and reuses the backend-stored launch
configuration; passing any launch option is rejected client-side. Delete and
key rotation reject `self`.

This generic path does not inject any routes. Use `createOpenClaw(...)` when you want the standard root gateway and `desktop` routes.

Create/start options:

- `name`
- `size`
- `config`
- `tags`
- `env`
- `ports`
- `routes`
- `command`
- `entrypoint`
- `restart`
- `image`
- `registryUrl`
- `registryAuth`
- `gatewayToken`
- `dryRun`

`registryUrl`, `registryAuth`, `syncRoot`, `syncEnabled`, and `restart` are
generic launch options. They belong to the base deployment contract, not to
OpenClaw specifically. Omit `restart` to preserve the platform default, or set
`restart: false` for a one-shot process that should leave the deployment
stopped after its main container exits.

## OpenClaw Presets

Use the OpenClaw-specific helpers when you want the SDK to provide the standard gateway and desktop routes:

```ts
const agent = await client.deployments.createOpenClaw({
  name: "docs-demo",
  start: true,
  tags: ["team=dev"],
});
```

Default OpenClaw routes are:

- `openclaw`
  - `prefix: ""`
  - `port: 18789`
- `desktop`
  - `prefix: "desktop"`
  - `port: 3000`

Route semantics are explicit:

- omit `routes`
  - SDK injects the standard OpenClaw routes
- pass `routes: {}`
  - no routes are created
- pass a non-empty `routes` object
  - SDK uses exactly what you passed

The same contract applies to `startOpenClaw(...)`.

Use `createOpenClawPro(...)` or `startOpenClawPro(...)` for the desktop/browser flavor. The pro helpers inherit the same OpenClaw defaults, select the `hypercli-openclaw:pro-prod` image when no image is provided, set `OPENCLAW_DESKTOP_ENABLED=1`, and include the protected noVNC route at `desktop-<agent>.hypercli.app`.

OpenClaw helpers only add defaults on top of that generic launch surface:

- `image`
  defaults to the published OpenClaw image when omitted
- `routes`
  defaults to the standard `openclaw` and `desktop` routes when omitted
- `syncRoot`
  defaults to `/home/node`
- `syncEnabled`
  defaults to `true`
- `heartbeat`
  maps to upstream OpenClaw config at `config.agents.defaults.heartbeat`

Omit `heartbeat` to keep upstream OpenClaw defaults. Pass values like `heartbeat: { every: "1h", target: "last" }` only when you intentionally want to tune upstream heartbeat behavior.

Memory search is configured by default, but automatic indexing is off unless you opt in. Use `memoryIndex` on `createOpenClaw(...)`, `createOpenClawPro(...)`, `startOpenClaw(...)`, or `startOpenClawPro(...)`:

```ts
const agent = await client.deployments.createOpenClaw({
  name: "indexed-agent",
  memoryIndex: {
    onSessionStart: true,
    onSearch: true,
    watch: true,
    watchDebounceMs: 30000,
    intervalMinutes: 0,
  },
});
```

Supported fields are `enabled`, `onSessionStart`, `onSearch`, `watch`, `watchDebounceMs`, and `intervalMinutes`. The defaults keep search enabled and set all automatic sync triggers off, with `watchDebounceMs=30000` and `intervalMinutes=0`.

Registry settings are still inherited from the generic deployment API:

```ts
const agent = await client.deployments.createOpenClaw({
  name: "private-image-demo",
  registryUrl: "git.nedos.co",
  registryAuth: { username: "ci", password: "token" },
});
```

## Hosted Coding Agents

The SDK has typed launch helpers for six non-OpenClaw runtimes:

| Runtime value | TypeScript helper | Generic default image |
| --- | --- | --- |
| `buzz-agent` | `createBuzzAgent()` | `ghcr.io/hypercli/hypercli-buzz-agent:latest` |
| `opencode` | `createOpenCode()` | `ghcr.io/hypercli/hypercli-opencode:latest` |
| `codex` | `createCodex()` | `ghcr.io/hypercli/hypercli-codex:latest` |
| `claude-code` | `createClaudeCode()` | `ghcr.io/hypercli/hypercli-claude-code:latest` |
| `goose` | `createGoose()` | `ghcr.io/hypercli/hypercli-goose:latest` |
| `kimi-code` | `createKimiCode()` | `ghcr.io/hypercli/hypercli-kimi-code:latest` |

These runtimes have no OpenClaw gateway and no public route by default.
Lifecycle, files, exec, shell, workspace sync, and interactive authentication
use the authenticated deployment API:

```ts
const codex = await client.deployments.createCodex({ name: "codex" });
const methods = await codex.auth.methods();
const status = await codex.auth.status();
const login = await codex.auth.login({ method: "device" });

console.log(login.verificationUrl, login.userCode);
await login.wait();
```

Authentication remains runtime-specific:

| Runtime | Current SDK behavior |
| --- | --- |
| OpenCode | Discovers adapter methods and exposes interactive provider login and logout |
| Codex | Discovers adapter methods and adds native device login, status, and logout |
| Claude Code | Discovers adapter methods and adds Claude.ai, Console, and SSO login, status, and logout |
| Goose | Uses adapter discovery/status with the injected deployment credential; no noninteractive logout |
| Kimi Code | Uses the upstream adapter's discovery/status and login methods; no noninteractive logout |

OpenCode and Goose images default to HyperCLI's Anthropic-native
`kimi-k2.6-anthropic` route. Kimi Code keeps Moonshot's upstream service and
login flow. Login sessions use an agent-bound shell WebSocket and never put an
API key on the command line; runtime credentials persist under `/home/node`.
See [Coding runtimes and persistence](/agents/coding-runtimes) for the complete
inference, authentication, and selective-sync matrix.

### Typed Buzz launches

Pass the typed `buzz` object to render the identity and canonical ACP launch:

```ts
const agent = await client.deployments.createOpenCode({
  name: "buzz-opencode",
  buzz: {
    privateKeyNsec: agentNsec,
    relayUrl,
    authTag: ownerSignedAuthTag,
    model: "hypercli/kimi-k2.6-anthropic",
  },
});
```

A managed launch receives its agent-scoped inference credential from the
platform as `HYPER_AGENTS_API_KEY`; callers should not copy an account API key
into the runtime environment.

A typed Buzz launch:

- leaves size unset for live backend/provider slot selection and sets
  `restart: false`;
- clears public routes and selects `/usr/local/bin/buzz-acp`;
- derives the selected runtime's ACP child command and Buzz MCP command;
- selects the matching `ghcr.io/hypercli/hypercli-buzz-<runtime>:latest`
  image, with Claude using `hypercli-buzz-claude`;
- keeps `syncRoot: "/home/node"` and reserves `/home/node/workspaces` for
  Workspace projections;
- runs from the image-managed `/home/node/.buzz` nest.

The nest is reconciled after the persistent home mount. OpenCode and Codex
consume its canonical `AGENTS.md`, while Claude Code receives
`CLAUDE.md -> AGENTS.md`. `base_prompt.md` remains compiled into `buzz-acp`.
An explicit `image` overrides the default. `buzzEnabled` is the deprecated
raw-environment compatibility path and cannot be combined with a typed `buzz`
value or explicit `command`.

The typed SDK renderer checks required identity fields and parallelism but does
not duplicate every stock Desktop cross-field validation. The Desktop provider
also maps structured Goose model/provider fields to
`GOOSE_MODEL`/`GOOSE_PROVIDER`; direct SDK callers must set Goose-specific
environment when needed.

Stock Buzz invokes providers only for `info` and `deploy`. It has no provider
stop callback. A successfully delivered and accepted `!shutdown` can exit a
new one-shot launch; hosted cleanup reports `stopping`, then `stopped`, and
releases the slot. Desktop receives no acknowledgement and retains its local
deployed record. See [Buzz Desktop](/agents/buzz) for the full protocol,
message-publishing, ownership, and security boundaries.

## Routes

Routes are a generic dict keyed by route name. Outside the OpenClaw helper methods, the SDK does not inject route defaults.

```ts
const agent = await client.deployments.create({
  name: "docs-demo",
  start: true,
  routes: {
    app: { prefix: "app", port: 8080, auth: false },
    admin: { prefix: "admin", port: 8081, auth: true },
  },
});
```

## Lifecycle

```ts
await client.deployments.list();
await client.deployments.get(agent.id);
await client.deployments.start(agent.id);
await client.deployments.stop(agent.id);
await client.deployments.delete(agent.id);
const running = await client.deployments.waitForState(
  agent.id,
  ["RUNNING"],
  300_000,
  ["FAILED", "RESTORE_FAILED", "SYNC_FAILED"],
);
```

`stop()` returns the accepted lifecycle state, normally `stopping`. Cleanup is
asynchronous; use `waitForState()` before restarting it or treating its slot as
available. The older polling-interval argument to `waitRunning()` is deprecated
and ignored.

### Subscribe to lifecycle invalidations

```ts
const controller = new AbortController();

const subscription = client.deployments.subscribe(async () => {
  const agents = await client.deployments.list();
  render(agents);
}, { signal: controller.signal });

// During application teardown:
controller.abort();
await subscription;
```

The subscription runs until aborted or a permanent authentication error
occurs. Events are thin, best-effort hints, not snapshots. The SDK reconnects
with backoff and completes a full REST resync before delivering further
invalidations. `AgentState` is intentionally open to future server states.

## Files And Exec

```ts
const result = await agent.exec("uname -a", { timeout: 30 });
console.log(result.stdout, result.exitCode);

await agent.fileWrite("/workspace/notes.txt", "hello");
const text = await agent.fileRead("/workspace/notes.txt");

await agent.cpTo("./local.txt", "/workspace/local.txt");
await agent.cpFrom("/workspace/output.log", "./output.log");
```

## Logs And Shell

Recommended helpers:

```ts
const logs = await client.deployments.logsConnect(agent.id, { tailLines: 200 });
const shell = await client.deployments.shellConnect(agent.id, "/bin/bash");
```

These use:

- `/api/deployments/{id}/logs/token`
- `/api/deployments/{id}/shell/token`
- backend `/ws/logs/{agent_id}`
- backend `/ws/shell/{agent_id}`

Prefer these over direct executor-era HTTP assumptions.

### Gateway URL Semantics

The SDK derives gateway connection context from:

```ts
`wss://${agent.hostname}`
```

That matches the current root-host gateway model.
