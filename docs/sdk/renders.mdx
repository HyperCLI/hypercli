## Catalog and submission

```python
from hypercli import HyperCLI

client = HyperCLI()
catalog = client.renders.catalog()
print(catalog["ltx23"]["templates"]["video_ltx2_3_ia2v"])
render = client.renders.submit("ltx23", "video_ltx2_3_ia2v", {
    "value": "a presenter speaking naturally",
    "input": {"file_id": owned_image_id},
    "audio": {"file_id": owned_audio_id},
    "noise_seed": 0,
    "start_index": 0,
    "value_4": 9,
})
```

Use the existing server catalog for exact names, types, defaults, writable flags
and required media. Submit only writable inputs. Labels are display text, not
aliases. Strings such as `"42"`, `False` and `0` retain their types. Media must
be caller-owned file IDs obtained from file uploads, not URLs, paths or inline data.

The standard catalog contains exactly five templates:

| Family | Template |
| --- | --- |
| `qwen21` | `image_qwen_image_2_1_t2i` |
| `qwen21` | `image_qwen_image_2_1_image_edit` |
| `ltx23` | `video_ltx2_3_t2v` |
| `ltx23` | `video_ltx2_3_i2v` |
| `ltx23` | `video_ltx2_3_ia2v` |

These are standard Qwen templates, not separately named distilled variants.
IA2V uses `value` (prompt), `input` (first frame), `audio`, `noise_seed`,
`start_index` (audio start) and `value_4` (duration). Qwen edit's fifth image
is the literal key `"images.image_5_1"`, bound to `{"file_id": owned_file_id}`.

## Routing and transport

Catalog discovery reads `/agents/flow/catalog` directly without entitlement routing.
For submission, the authoritative `/agents/flow/access` boolean `render` selects included versus
account submission. The SDK does not infer access from capabilities or subscription
metadata. Discovery failure aborts submission. Included submissions use
`/agents/flow/catalog`; account submissions use `/api/renders`. A rejected included
submission is not retried as paid. Submission POSTs have one transport attempt;
GET retries remain enabled. Retain the ID; do not automatically resubmit after
an uncertain response.

## Tracking

```python
client.renders.list(state="completed")
status = client.renders.status(render.render_id)
print(status.state, status.progress)
final_render = client.renders.wait(render.render_id, poll_interval=2, timeout=1800)
print(final_render.state, final_render.result_url, final_render.error)
details = client.renders.get(render.render_id)
```

`wait` returns completed, failed and cancelled records; callers must check `state`.
Pending/running is acceptance, not completion. Cancel with
`client.renders.cancel(render.render_id)` when requested. Legacy `create_flow` and
named helpers remain compatibility interfaces; prefer `catalog` and `submit` for
exact current templates. `create` is the lower-level account render API.
