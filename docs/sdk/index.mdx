## What The Python SDK Covers

The Python SDK has two distinct halves:

- HyperCLI platform APIs
  - billing
  - jobs
  - instances
  - renders
  - files
  - keys
  - user
  - voice
- HyperCLI / agent APIs
  - `client.agent` for plan and model metadata
  - `client.deployments` for agent lifecycle and runtime access

```python
from hypercli import HyperCLI

client = HyperCLI(
    api_key="hyper_...",      # main HyperCLI API key
    agent_api_key="hyper_api_...",   # optional agent-scoped key
)
```

## Authentication Model

The constructor resolves credentials in this order:

1. explicit constructor args
2. environment variables
3. `~/.hypercli/config`

Common environment variables:

- `HYPER_API_KEY`
- `HYPER_API_BASE`
- `HYPER_AGENTS_API_BASE`
- `HYPER_AGENTS_API_KEY`

The retired overrides `HYPERCLI_API_KEY`, `HYPERCLI_API_URL`, `HYPERCLI_WS_URL`,
`AGENTS_API_BASE_URL`, and `AGENTS_WS_URL` are not read. `HYPER_API_BASE` selects
product/inference; `HYPER_AGENTS_API_BASE` independently selects direct Agent
control, never inference. Agent endpoints derive from the product base only
when no Agents base is supplied.

Use canonical `api_key` for an explicit credential. Otherwise clients resolve
environment `HYPER_API_KEY`, the configured canonical key, then environment
`HYPER_AGENTS_API_KEY` as the final fallback for product and agent APIs.

## Quick Start

```python
from hypercli import HyperCLI, build_openclaw_desktop_route

client = HyperCLI(api_key="hyper_...")

agent = client.deployments.create(
    name="docs-demo",
    runtime="openclaw",
    image="ghcr.io/hypercli/hypercli-openclaw:prod",
    sync_root="/home/node",
    routes=build_openclaw_desktop_route(),
    env={"APP_ENV": "prod", "HYPER_DESKTOP_ENABLED": "1"},
)

agent = client.deployments.wait_for_state(agent.id, {"stopped"}, timeout=330)
agent = client.deployments.start(agent.id)
agent = agent.wait_running(timeout=300)
print(agent.public_url)   # https://docs-demo.hypercli.app
print(agent.desktop_url)  # https://desktop-docs-demo.hypercli.app
```

## Current Agent Route Model

For OpenClaw-backed agents, the platform defaults are:

- `desktop-<host>` = desktop
- extra routes come from the `routes` dict you pass at create/start time

That means:

- `Agent.public_url` is the root host
- `Agent.desktop_url` and `Agent.vnc_url` point to `desktop-<host>`
- `Agent.shell_url` is only populated if you explicitly create a `shell` route

There is no default `shell-<host>` platform route anymore.

## Recommended Access Patterns

### Use `client.user.auth_me()` for capability introspection

The Python SDK exposes the current auth context, including resolved key capabilities:

```python
auth = client.user.auth_me()
print(auth.auth_type)
print(auth.capabilities)
print(auth.key_id)
```

This resolves against the main product auth route at `/api/auth/me`.

On Orchestra-backed product surfaces, scoped keys generally need `user:self`
for this call. A flow-only key can still use `client.renders.*` helpers,
because the SDK falls back to `/api/flow/*` when auth introspection is denied.

### Use `client.voice` for subscription voice routes

Voice helpers go through the current `/agents/voice/*` surface:

```python
audio = client.voice.clone("Hello from HyperCLI", ref_audio="reference.wav", response_format="mp3")

with open("hello.mp3", "wb") as f:
    f.write(audio)
```

Cloning is the supported speech-generation path for new integrations. Preset TTS
and design helpers remain available for legacy compatibility.

The Python SDK sends these requests through the derived agents API base. For
`api_url="https://api.hypercli.com"`, `client.voice.clone(...)` posts to
`https://api.hypercli.com/agents/voice/clone`.

Streaming voice uses the agents WebSocket base plus `/voice`:

```python
async with client.voice.connect() as session:
    async for chunk in session.speak_clone("Hello from HyperCLI", ref_audio="reference.wav"):
        handle_audio(chunk.audio)

async for chunk in client.voice.clone_stream("Hello from HyperCLI", ref_audio="reference.wav"):
    handle_audio(chunk.audio)
```

**WebSocket compatibility change:** generation now defaults to raw PCM, not MP3,
in both convenience calls and `VoiceSession`. Chunked PCM automatically requests
`stream_mode="incremental_pcm"`; no extra caller flag is needed. Only an echoed
START acknowledgement enables unknown `chunk.total` (`None`), with the exact count
validated at DONE. Older servers without the acknowledgement retain known totals
and final markers. Use audio metadata to play PCM; it is not an MP3 file. Pass
`response_format="mp3"` explicitly for encoded output. REST and CLI file defaults
are unchanged. `chunks=False` requests assembled audio without automatic
incremental negotiation. Preset TTS and VoiceDesign APIs have been removed;
synthesis requires reference audio.

The streaming request frame is a JSON message with `type="speak"`, an
`op="clone"`, required reference audio in `ref_audio_base64`, a `request_id`,
`format`, and `chunks`.
The server replies with `start`, then ordered `audio` JSON headers followed
immediately by binary payload frames, then `done`; server errors raise
`VoiceStreamError`. A session handles one request at a time, and breaking the
iterator early sends `{"type": "cancel"}` for the request.

### Use backend `/ws/*` for logs and shells

Preferred helpers:

- `agent.logs_stream_ws()`
- `agent.shell_connect()`
- `client.deployments.logs_stream_ws(...)`
- `client.deployments.shell_connect(...)`

These use backend-issued short-lived tokens and the backend `/ws/logs/{agent_id}` and `/ws/shell/{agent_id}` endpoints.
