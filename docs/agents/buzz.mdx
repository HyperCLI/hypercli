The public SDKs can render Buzz identity, relay, and runtime settings into a
managed deployment. The public repository contains SDKs and the CLI; it does
not contain the Buzz Desktop backend-provider executable or the HyperCLI
desktop app. Build and installation instructions for those separate products
are not part of this SDK guide.

## TypeScript launch configuration

The typed `buzz` option is available on `createAgent`. Supply the agent's
Nostr private key, relay URL, and owner-signed authorization tag from your Buzz
integration:

```ts
import { HyperCLI } from "@hypercli.com/sdk";

const client = new HyperCLI();
const agent = await client.deployments.createAgent("opencode", {
  name: "buzz-agent",
  buzz: {
    privateKeyNsec: process.env.BUZZ_AGENT_NSEC!,
    relayUrl: process.env.BUZZ_RELAY_URL!,
    authTag: process.env.BUZZ_AUTH_TAG!,
  },
});
await client.deployments.waitForState(agent.id, ["STOPPED"], 330_000);
await client.deployments.start(agent.id);
await client.deployments.waitForState(agent.id, ["RUNNING"], 300_000, ["FAILED"]);
```

This renders a launch request. It does not create an owner identity, enroll
channels, or install a desktop provider. The Python `create_agent` helper has
no typed `buzz` argument.

## Rust configuration

The Rust SDK exports `BuzzLaunchConfig`, `CreateDeploymentRequest`, and
`ManagedRuntime`. `BuzzLaunchConfig::apply_to` renders Buzz settings onto an
existing request. Set the request's image explicitly; the Rust SDK does not
select a runtime image. See the [Rust SDK](/rs-sdk/index) for source installation
and API documentation.

## Runtime and storage

Buzz launches retain the selected runtime's normal image unless explicitly
overridden. The launch renderer sets the command and Buzz environment and
disables restart. An explicit command cannot be combined with typed Buzz
configuration in the TypeScript helper.

The persistent root is `/home/node`; `/home/node/shared` is reserved for
Workspace projections. Runtime-specific sync policies and authentication
requirements are described in [coding runtimes](/agents/coding-runtimes).

The agent private key and caller environment become deployment environment
values. Treat access to deployment configuration, environment, and exec as
sensitive. The default logging filter disables ACP stream-content logging;
overriding it may expose generated text.

Use the public deployment APIs or [CLI](/cli/commands/agents) for status, logs,
stop, and delete. SDK request rendering alone does not establish desktop,
relay, or runtime end-to-end compatibility.
