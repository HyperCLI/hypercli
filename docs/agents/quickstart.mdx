## Prerequisites

1. A HyperCLI key:

   ```bash
   hyper agent subscribe solo
   ```

2. The CLI installed:

   ```bash
   pip install hypercli-cli
   ```

## Environment Variables

| Variable | Description | Default |
| --- | --- | --- |
| `HYPER_API_KEY` | Canonical API key; environment overrides the saved canonical key | `$HYPER_HOME/config`, default `~/.hypercli/config` |
| `HYPER_AGENTS_API_KEY` | Platform runtime key, used only after explicit and configured canonical credentials | Injected by Lagoon in managed runtimes |
| `HYPER_API_BASE` | Product API base; the agents REST and shell/log WebSocket bases are derived from it | `https://api.hypercli.com` |

## Create An Agent With The CLI

```bash
hyper agents create --name my-agent --size small
# after status reports STOPPED:
hyper agents start my-agent
hyper agents status my-agent
hyper agents exec my-agent echo hello world
hyper agents shell my-agent
hyper agents chat my-agent
hyper agents stop my-agent --force
```

<Tip>
The CLI supports ID prefix matching from cached state in `~/.hypercli/agents.json`.
</Tip>

## Create An Agent With The Python SDK

```python
from hypercli import HyperCLI

client = HyperCLI(api_key="...", agent_api_key="hyper_api_...")

agent = client.deployments.create(
    name="my-agent",
    size="small",
    runtime="openclaw",
    image="ghcr.io/hypercli/hypercli-openclaw:prod",
    sync_root="/home/node",
)
agent = client.deployments.wait_for_state(agent.id, {"stopped"}, timeout=330)
agent = client.deployments.start(agent.id)
agent = client.deployments.wait_running(agent.id, timeout=300)
print(agent.id, agent.state, agent.vnc_url)

result = client.deployments.exec(agent, ["echo", "hello world"])
print(result.stdout)

client.deployments.file_write(agent, "/tmp/test.txt", "Hello from SDK!")
content = client.deployments.file_read(agent, "/tmp/test.txt")
print(content)

client.deployments.stop(agent.id)
```

Create returns the admission snapshot, normally `CREATING`. Wait explicitly for
authoritative `STOPPED` before writing files or starting. Lifecycle wait helpers
use deployment events to wake an authoritative REST check. `status`, `get`, and
`list` remain one-shot REST snapshots.

## Receive Lifecycle Updates

Applications can subscribe to thin deployment invalidations. The SDK performs
the initial REST load, authenticates the account stream, waits for `ready`, and
reads REST again before delivering events. Re-read REST in the handler rather
than treating the event as a resource snapshot:

```python
import asyncio

async def main():
    stop = asyncio.Event()

    async def changed(_event):
        agents = await asyncio.to_thread(client.deployments.list)
        print([(agent.name, agent.state) for agent in agents])

    await client.deployments.subscribe(changed, stop_event=stop)

asyncio.run(main())
```

The stream is best effort. SDKs reconnect with backoff and perform a complete
REST resync; duplicate or coalesced invalidations are harmless. There is no
client ACK, resume cursor, or per-client durable outbox.
