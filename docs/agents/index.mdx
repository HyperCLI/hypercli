## What Are Agents?

Agents are fully managed **OpenClaw desktop containers** that run on Kubernetes. Each agent provides:

- **Desktop** — full Linux desktop accessible via browser
- **Shell access** — backend WebSocket PTY terminal
- **File system** — read/write files on the container
- **OpenClaw Gateway** — WebSocket RPC for AI chat, config, cron, and more

Agents are ideal for running autonomous AI workflows, development environments, or any task that needs a persistent Linux desktop with programmatic control.

## Architecture

```
Client (CLI / SDK)
    │
    ▼
HyperCLI Backend API (api.hypercli.com)
    │  Auth, plan enforcement, DB persistence
    ▼
Lagoon (pod orchestrator)
    │  Scheduling, health monitoring, log ingest
    ▼
Agent containers on Kubernetes
    ├── Desktop (noVNC)
    └── OpenClaw Gateway (WebSocket RPC v3)
```

The HyperCLI backend handles authentication and plan enforcement. It proxies lifecycle commands to **Lagoon**, which orchestrates `hypercli-openclaw` agent containers on the underlying Kubernetes cluster.

## Hostnames

Each agent gets a root gateway host plus optional prefixed routes:

| Service  | URL Pattern                              | Protocol   |
|----------|------------------------------------------|------------|
| Gateway  | `wss://{name}.hypercli.app`             | WebSocket  |
| Desktop  | `https://desktop-{name}.hypercli.app`   | HTTPS/noVNC |
| Custom   | `https://{prefix}-{name}.hypercli.app`  | HTTPS/WSS  |

Desktop is available on the OpenClaw pro image. The base OpenClaw image keeps the root gateway route only unless callers explicitly add more routes.

Current auth split:

- gateway uses application-level auth inside OpenClaw
- protected browser routes use `/_jwt_auth?jwt=...` bootstrap
- shell/log streaming uses backend `/ws/*` endpoints, not a dedicated shell host

## Lifecycle

Agents move through these states:

```
create → pending → starting → running → stopping → stopped → deleted
```

| State      | Description                                                   |
|------------|---------------------------------------------------------------|
| `pending`  | Created in DB, waiting for pod scheduling                     |
| `starting` | Pod scheduled, containers initializing                        |
| `running`  | All containers healthy, endpoints accessible                  |
| `stopping` | Runtime and namespace cleanup accepted but still in progress   |
| `stopped`  | Cleanup confirmed, DB record preserved, deployment slot freed  |
| `deleted`  | Fully removed (pod + DB record)                               |

Do not treat `stopping` as stopped: its namespace can still exist and its
deployment slot remains occupied. Stopped agents retain their configuration
and can be restarted. Deleted agents are gone permanently.

## Health Monitoring

Agent health is monitored via **app-level ping/pong** over the Lagoon log ingest WebSocket — not by direct HTTP probing. This approach:

- Works through Traefik ingress without exposing health endpoints
- Detects application-level hangs (not just TCP connectivity)
- Integrates with the existing log streaming infrastructure

## Resources

HyperCLI billing now has two additive ledgers:

- **Inference** pools across all active entitlements
- **Agents** are tracked as exact-tier slots (`small`, `medium`, `large`)

Check your current slot inventory and pooled inference with:

```bash
hyper agents budget
```

### Size Presets

| Size | Advertised CPU / memory |
| --- | --- |
| `small` | 0.5 CPU / 2 GiB |
| `medium` | 1 CPU / 4 GiB |
| `large` | 2 CPU / 8 GiB |

These are the customer-facing machine shapes. Billing is enforced by tier
count, not by summing CPU and RAM across the account. Kubernetes scheduling
requests and burst ceilings are private backend-to-Lagoon implementation data.

Examples:

- `5x small` + `5x large` lets you run 10 agents total: 5 small and 5 large
- `10x large` lets you run 10 large agents
- buying another plan unit adds another entitlement window, its included
  slots, and more pooled inference

<Tip>
Use `hyper agents budget` to see granted, used, and available slots by tier before creating or starting agents.
</Tip>
