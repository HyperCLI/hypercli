---
title: OpenClaw Runtime Config
description: How managed OpenClaw agents ship and persist runtime configuration.
---

Managed HyperCLI Agents run OpenClaw with a persisted runtime config at:

```text
/home/node/.openclaw/openclaw.json
```

This file is inside the managed agent sync root. For standard OpenClaw agents,
the sync root is `/home/node`, so runtime config changes are backed up with the
rest of the agent state.

## Update Path

There is no public gateway RPC surface: the pod gateway binds loopback with
auth mode `none` as an ACP hop only. Edit the config over the deployment file
API, then restart the agent so OpenClaw re-reads it:

```python
config = client.deployments.file_read(agent, "/home/node/.openclaw/openclaw.json")
# mutate JSON...
client.deployments.file_write(agent, "/home/node/.openclaw/openclaw.json", updated)
client.deployments.stop(agent.id)
client.deployments.start(agent.id)
```

The image entrypoint reconciles the rendered config at boot (`config.ts`) and
sheds stale gateway-era auth blocks, so a hand-edited config is normalized to
the ACP-era shape on first boot.

## Persistence

When an agent has state sync enabled:

1. OpenClaw writes the updated config to `/home/node/.openclaw/openclaw.json`.
2. The sync sidecar mirrors `/home/node` to the agent backup.
3. On restart, the restore init container restores the backup before OpenClaw
   starts.
4. The OpenClaw image entrypoint only copies the baked template if the runtime
   config file is missing after restore. It no longer runs a redundant
   `openclaw config validate` pass during boot.

This means config updates are expected to survive normal container
restarts.

Public launch-config patches are complete replacements for launch fields, but
the backend can preserve stored redacted `secrets` and `registry_auth` when
they are omitted from a PATCH. START is different: owner-facing Agent
projections never return `registry_auth`, so callers using private registry
images must supply those credentials again when rebuilding a START payload.
Storage settings are retained after provisioning; do not use a public
launch-config patch to change an agent's provisioned retained-storage shape.

## Template Recovery

The image includes a baked config template. That template is used only to
bootstrap a missing runtime config.

If you delete `/home/node/.openclaw/openclaw.json` in a running persisted agent
and then restart it, the backup may restore the previous config. To force a
fresh template, the persisted backup copy must also be absent, or the agent must
start without restored state.

Use this behavior intentionally:

- update Slack, WhatsApp, Telegram, and other channel settings via file edits
  plus a restart
- rely on sync for persistence
- use the baked template as a recovery/default source for fresh state

## Operational Check

For integration changes that must be durable, verify by reading the config back
after the restart test:

1. Edit a harmless channel config value.
2. Restart the agent.
3. Read it back and confirm the value survived.

For boot readiness, treat `config-applied` as the config handoff/ready point.
It is not a promise that a separate "config verified" log line was emitted.
