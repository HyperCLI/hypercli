## Overview

Use `x402-wallet` when you want to buy HyperCLI agent entitlements without a browser checkout flow.

- Checkout endpoint: `POST https://api.hypercli.com/agents/x402/{plan_id}`
- Token: USDC on Base
- Payment transport: x402 HTTP 402 + signed EIP-3009 payload

Each successful payment creates one or more direct entitlement records for the
selected plan. It does not create a recurring subscription. Entitlements stack:

- inference is pooled across all active entitlements
- agent slots are added by exact tier
- repeated purchases of the same plan add more capacity

The x402 amount is also duration-aware. Paying the full plan price grants 30
days with the current production configuration. Smaller amounts buy shorter
windows when they satisfy the configured minimum payment floor. This differs
from the current Stripe entitlement window configuration (`duration_days: 32`).

## Flow

1. Call `POST /agents/x402/{plan_id}` without payment headers
2. Receive HTTP 402 payment requirements
3. Sign payment with your x402 wallet
4. Retry with the payment header generated by the x402 client
   (`PAYMENT-SIGNATURE` for x402 v2; `X-PAYMENT` for v1)
5. Receive the activated entitlement details, expiry, and plan-unit limits

## Example (curl + wallet-managed payment payload)

```bash
# Initial request (expect 402)
curl -i -X POST https://api.hypercli.com/agents/x402/solo

# Retry with signed payment payload
curl -X POST https://api.hypercli.com/agents/x402/solo \
  -H "PAYMENT-SIGNATURE: <signed-payment-payload>"
```

## Response

```json
{
  "ok": true,
  "key": "hyper_api_...",
  "plan_id": "solo",
  "quantity": 1,
  "contract_version": "2026-08",
  "amount_paid": "39.000000",
  "duration_days": 30.0,
  "expires_at": "2026-09-03T12:00:00+00:00",
  "tpm_limit": 868050,
  "rpm_limit": 86
}
```

The timestamps and derived TPM/RPM values in a real response come from the
active plan and rate-limit configuration; do not treat the example as a fixed
contract.

For additive agent billing, think of that response as one more active entitlement. If you buy the same plan twice, you now have two entitlement windows contributing pooled inference and tier slots.

## Auth Modes

- With JWT Bearer token: entitlements and payment records are linked to that account
- Without JWT: the backend creates or reuses a wallet-backed user, creates the
  entitlements and payment records, and returns a usable key

See [Agents API](/agents/api) for checkout semantics and duration calculation details.
