Python and TypeScript managed-runtime helpers select image and storage settings
for each runtime. Prefer choosing the runtime rather than copying an image
default from an older example.

## Image families

All image names below are under `ghcr.io/hypercli/`.

| Runtime | SDK runtime | Image repository |
| --- | --- | --- |
| OpenClaw | `openclaw_acp` | `hypercli-openclaw` |
| Hermes | `hermes_acp` | `hypercli-hermes` |
| Buzz Agent | `buzz-agent` | `hypercli-buzz-agent` |
| OpenCode | `opencode` | `hypercli-opencode` |
| Goose | `goose` | `hypercli-goose` |
| Codex | `codex` | `hypercli-codex` |
| Claude Code | `claude-code` | `hypercli-claude` |
| Kimi Code | `kimi-code` | `hypercli-kimi-code` |
| Pi | `pi` | `hypercli-pi` |

OpenClaw desktop uses the same image with explicit environment and routes.
Buzz configuration retains the chosen coding runtime's image. Generic
deployments and Rust requests require an explicit image selection.

## Tags and overrides

The production channel is `:prod`; `:latest` is the development channel.
These are mutable tags, not release-version or immutable build identifiers.
Current Python and TypeScript helpers default OpenClaw to `:prod`, but Hermes
and all seven coding runtimes still default to `:latest`. These defaults do
not yet select the channel based on the API environment. Pass an explicit
`image` option to select the intended channel.

```ts
const agent = await client.deployments.createAgent("opencode", {
  name: "custom-image",
  image: "ghcr.io/hypercli/hypercli-opencode:prod",
});
```

An image name in this catalog does not prove that a particular candidate build
has been published or passed a live runtime test. Check the selected registry
tag when choosing a custom build. See [coding runtimes](/agents/coding-runtimes)
for authentication and persistence defaults.
