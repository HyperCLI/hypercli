---
title: Coding Runtimes and Persistence
description: Inference, authentication, and selective-sync defaults for managed coding agents, OpenClaw, and Hermes
---

HyperCLI provides six ACP coding-runtime container families plus the OpenClaw
and Hermes gateway-style runtimes. The ACP families and OpenClaw use
`/home/node`; Hermes uses `/home/hermes`. They do not all use the same inference,
API-authentication, or backup policy.

The Python and TypeScript coding-agent helpers apply the defaults below. A
Buzz-managed launch selects the corresponding `hypercli-buzz-*` image and adds
`buzz-acp`; it does not change the runtime's native authentication intent.

## Runtime matrix

| Runtime | Default inference and authentication | Default selected state | Important limitations |
| --- | --- | --- | --- |
| Buzz Agent | HyperCLI-first. The platform injects the agent-scoped inference credential; there is no separate runtime login. | Whole root (selector omitted) | Identity and inference credentials are environment-owned. Choose a custom policy if you intentionally want narrower home-directory backup. |
| OpenCode | HyperCLI-first through the image's `hypercli` provider. Upstream provider login remains available when you configure another provider. | `.config/opencode`, `.local/share/opencode`, `.local/state/opencode`, `.cache/opencode` | Models are provider-qualified, for example `hypercli/kimi-k2.6-anthropic`. |
| Codex | Native-first through the Codex/OpenAI device-login flow. | `.codex` | The gateway now exposes `/v1/responses`, and Buzz compatibility mode renders `wire_api="responses"`; a successful HyperCLI-model Codex Responses E2E is still unvalidated, so this path is not yet advertised as supported. |
| Claude Code | Native-first through Claude.ai, Console, or SSO login. | `.claude`, `.claude.json` | In a Buzz-managed launch only, `HYPERCLI_RUNTIME_INFERENCE=hypercli` explicitly selects the HyperCLI Anthropic-compatible path. It is never enabled implicitly. |
| Goose | HyperCLI-first through the image's injected `hypercli` provider and agent-scoped credential. | `.goose` | No separate vendor login is required for the default. Direct SDK callers that bypass the typed provider mapping must supply Goose-specific provider settings themselves. |
| Kimi Code | Native-first through Kimi/Moonshot's device-login flow. | `.kimi-code` | In a Buzz-managed launch only, `HYPERCLI_RUNTIME_INFERENCE=hypercli` explicitly selects the HyperCLI compatibility provider. The SDK surface has no noninteractive logout. |
| OpenClaw | HyperCLI-first through the managed image's `hypercli` provider. No vendor login is needed for that default; OpenClaw gateway authentication is a separate application-level token. | `/home/node` minus Workspace projections, package caches, reindex scratch files, and browser caches | OpenClaw is a gateway runtime, not an ACP coding harness. Update its persisted `.openclaw/openclaw.json` through gateway config RPCs rather than writing it directly from application code. |
| Hermes Agent | HyperCLI-first through the managed image's backend-injected model credential. Its HTTP API Server uses a separate generated `API_SERVER_KEY`. | `/home/hermes` minus `shared/**`, UID/GID 10000 | Hermes is an API/SSE gateway runtime, not an ACP harness. The API key is write-only launch material; a later list/get cannot recover it. |

Claude Code, Codex, and Kimi Code images expose the normalized
`/usr/local/bin/hypercli-runtime-auth` wrapper. Their login commands run inside
the hosted container and store native credentials under the selected persistent
state paths. Login therefore requires a running deployment. OpenCode exposes
its adapter login methods; Buzz Agent and Goose need no login for their default
HyperCLI inference path.

`HYPERCLI_RUNTIME_INFERENCE=hypercli` is interpreted at the `buzz-acp` child
spawn boundary. It is an explicit compatibility switch for Buzz-managed
Claude Code and Kimi Code launches, not a universal setting for arbitrary
direct containers. Explicit native provider environment always wins as a
complete configuration; HyperCLI does not mix a vendor URL with a platform
credential.

Hermes launches as runtime `hermes-agent` with
`ghcr.io/hypercli/hypercli-hermes-agent:latest`, enables its API Server on port
8642, and exposes the route named `hermes`. The SDK generates or accepts the
separate API-server key and never substitutes it for the backend-injected
model credential. Python and TypeScript retain it only on the agent object
returned by create/start; Rust retains it on `HermesLaunchConfig`. Python,
TypeScript, and Rust expose Hermes-native health, session, run, and SSE helpers;
use the returned `/v1` base URL with an OpenAI client for the API Server's
OpenAI-compatible resources.

## Selective-sync contract

The coding-runtime defaults are ordinary launch settings, not a hidden
platform blacklist. Python uses `sync_include` and `sync_exclude`; TypeScript
uses `syncInclude` and `syncExclude`.

- A custom include list replaces the runtime default.
- A custom exclude list selects full-root-minus-excludes mode when no include
  list is active.
- Include wins when both custom policies are supplied; the clients serialize
  only the active policy.
- An explicit empty include list is invalid.
- On generic create, supplying a sync root with neither policy field selects
  the complete root (`/home/node` for the ACP/OpenClaw families, `/home/hermes`
  for Hermes). Explicit `null` has the same full-root meaning. An empty
  exclude list also excludes nothing.
- Paths are relative to the sync root. Do not use absolute paths or `..`.

The OpenClaw helpers do not use the generic full-root default. They exclude
`shared/**` (Workspace projections), `.openclaw/npm/**/node_modules/**`,
`.openclaw/agents/**/agent/*.sqlite.memory-reindex-*`,
`.openclaw/agents/**/agent/*.sqlite.reindex-lock.sqlite*`, and the browser
`Code Cache/**`, `GPUCache/**`, `ShaderCache/**`, `GrShaderCache/**`, and
`optimization_guide_model_store/**` trees. Pass an explicit `null` policy at
creation when full-root persistence is intentional.
The Hermes helper follows the OpenClaw Workspace convention: `/home/hermes`
is retained, while `shared/**` is excluded from Reef/S3 backup because
Workspace projections are boot-materialized and can drift during sessions.
Hermes runtime state is owned by UID/GID 10000.
Coding runtimes default to the smallest roots needed to preserve their native
configuration, credentials, and state. HyperCLI Workspace projections under
`/home/node/shared` are a separate feature and are not added to a coding
runtime's selected backup paths automatically.

Older deployments whose stored launch contract has neither policy field retain
the historical full-root behavior. The sync root and policy are retained
storage settings chosen at creation; ordinary starts inherit them rather than
reselecting the storage contract.

## Data-flow and deletion semantics

The policy selects paths inside the persistent volume; it does not create a
continuous two-way filesystem. While the retained Reef pod is running, allowed
files flow from the PVC to the cluster object mirror. New and changed files are
uploaded, but an ordinary process deleting a file from the mounted filesystem
does not delete the remote object. A delete made through the authenticated
Files API is different: it performs a targeted local delete and a targeted
remote delete.

Remote objects flow back to the PVC only during an explicit cold restore.
Create does not import an old object prefix, and an ordinary start reuses the
existing PVC without pulling remote changes. Cold restore overwrites the
selected scope and removes selected local files that are absent from the
restore source. Reef always reserves `.reef-sync/**` and
`.reef-sync-upload/**`; those internal paths are excluded even in full-root
mode.

Archive is a storage-lifecycle boundary rather than another selective-sync
pass. After the runtime and steady watcher are quiescent, it copies and verifies
the complete PVC minus Reef's two internal paths, regardless of the user's
include/exclude policy, and then evicts the cluster-local object prefix. This
captures ordinary local deletions exactly in the committed archive. An empty
include still selects no user objects during restore; consequently, a cold
restore with that policy cannot currently prove a selected source and fails.

## Container families

Coding-agent helpers select the supported public image for the requested
runtime. Buzz-managed launches use
`ghcr.io/hypercli/hypercli-buzz-<runtime>:latest` and run the runtime behind
`/usr/local/bin/buzz-acp`; Claude's Buzz image is named
`hypercli-buzz-claude`. Buzz Agent already uses `hypercli-buzz-agent:latest`.
An explicit immutable `image` override still wins.

The coding runtimes have no OpenClaw gateway and no public route by default.
Use authenticated deployment lifecycle, files, exec, shell, and runtime-auth
APIs. OpenClaw instead exposes its gateway routes and should be controlled with
the OpenClaw-specific SDK helpers. Hermes exposes its API Server through the
`hermes` route and should be controlled with the Hermes SDK helpers. See
[Supported runtime images](/agents/images),
[OpenClaw runtime config](/agents/openclaw-config), and
[Buzz Desktop](/agents/buzz) for those runtime-specific control planes.
