## Set A Voice

In the desktop app, open the agent's **Settings** tab and use the voice row to
choose an audio clip — or drop one onto the picker dialog. Accepted formats:

- MP3
- WAV
- M4A
- OGG
- WebM
- MP4

Keep clips under 10 MB. The picker accepts files up to 15 MB, but the server
enforces 10 MB, so clips between 10 and 15 MB upload and then fail there.
Trim to fit. Use the same row to remove the voice.

## What A Voice Enables

An agent with a voice set unlocks the app's voice features:

- the speaker button in the chat header ([read-aloud](/agents/chat#read-aloud)), and
- the **Voice replies** switch on the agent's Settings tab, which persists per
  agent across sessions.

Both controls stay disabled until a clip is uploaded. If your deployment does
not expose the voice API, the picker row shows the feature as unavailable
instead of failing.

For text-to-speech, cloning, and transcription from the terminal, see
[`hyper voice`](/cli/commands/voice).

## Incremental PCM framing

Opt in on a voice session with `streamMode: 'incremental_pcm'` (TypeScript)
or `stream_mode='incremental_pcm'` (Python), PCM format and chunks enabled.
The wire `speak.stream_mode` must be echoed by `start.stream_mode` before
unknown audio totals are accepted. Older servers may ignore the request and
return the existing known-total/final framing, which new SDKs still accept.
Requests without the opt-in retain the old wire contract.

In the negotiated mode, `audio.total: null` means unknown, not an estimate.
`final` may be omitted for unknown totals; `done.total_chunks` must contain
the exact number of audio frames received. Sequence and byte-length checks
still apply. Closing the iterator cancels the request.

Source compatibility: `VoiceChunkEvent.total` is now `number | null` and
Python `VoiceChunk.total` is `int | None`; callers doing arithmetic or showing
progress must handle unknown totals. `final: false` does not imply another
frame will follow in this mode. Python chunks also carry start-frame metadata.
Release version remains governed by `versions.json` (0.8.3).

This removes operator-side whole-WAV buffering for opted-in WebSocket PCM.
The upstream Qwen worker still fully generates and encodes each text segment
before sending its first frame. This is not a model streaming or TTFA claim.
