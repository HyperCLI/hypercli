This page describes `@hypercli.com/cli`. Use `hyper agents --help` for the
command inventory and `hyper agents <command> --help` for flags.

## Create, start, and inspect

```bash
hyper agents create docs-demo --runtime openclaw --size small
hyper agents wait docs-demo --state STOPPED --timeout 330
hyper agents start docs-demo
hyper agents wait docs-demo --state RUNNING --timeout 300
hyper agents status docs-demo
hyper agents list --json
```

Create admits a deployment; start is a separate operation using its stored
launch configuration. START does not accept image, environment, or desktop
overrides. Status and list return snapshots; wait uses deployment events to
wake authoritative REST checks.

Runtime choices include `openclaw`, `hermes`, `generic`, `opencode`, `codex`,
`claude-code`, `goose`, `kimi-code`, `pi`, and `buzz`. Names and unambiguous
ID prefixes can be used to select agents.

Create options include `--image`, `--size`, repeated `--env KEY=VALUE` and
`--secret KEY=VALUE`, `--sync-root`, `--sync-include` or `--sync-exclude`,
registry credentials, runner placement, and `--dry-run`. Pass a custom
command after `--`. See [runtime images](/agents/images) and
[persistence](/agents/coding-runtimes).

```bash
hyper agents create custom --runtime generic --image example/agent:prod \
  --env LOG_LEVEL=info --dry-run -- /app/agent
```

`hyper agents set runtime <id> <runtime>` resets the stored launch image to
that runtime's default. Use it only when intentionally changing the runtime.

## Environment selection

```bash
HYPER_API_BASE=https://api.dev.hypercli.com hyper agents list
```

`HYPER_AGENTS_API_BASE` independently selects Agent control. When omitted,
the Agents endpoint derives from the product base. See
[configuration](/cli/configuration) for credential precedence.

## Chat and retained messages

```bash
hyper agents chat docs-demo "Summarize the project" --stream
hyper agents chat docs-demo "Continue" --session work
hyper agents messages <session-id> --limit 20
hyper agents messages <session-id> --cursor <cursor>
```

Chat uses ACP. `--cwd` supplies a runtime-host working directory;
`--mcp-servers FILE` supplies session MCP configuration. Permission policy is
selected with `--permissions auto|none`. Retained messages are platform REST
history, separate from ACP prompt completion. `messages --follow` emits current
snapshots rather than a durable event stream.

For runtime-native login:

```bash
hyper agents login docs-demo
```

Available login flows depend on the selected runtime.

## Exec, files, shell, and logs

```bash
hyper agents exec docs-demo -- uname -a
hyper agents cp ./local.txt docs-demo:local.txt
hyper agents cp docs-demo:output.log ./output.log
hyper agents shell docs-demo
hyper agents logs docs-demo -n 200 -f
```

Exec and shell use authenticated backend WebSockets; no public shell route is
required. File transfers obtain scoped credentials and transfer directly to
the agent file service. Relative remote paths are relative to the sync root;
the CLI also accepts absolute paths and `~/…`.

Captured logs support `--source both|stdout|stderr`,
`--generation current|previous`, `--max-bytes`, and `--max-lines`. Runner
captures are replacement snapshots, not a chronological merge of stdout and
stderr. Logs may contain application data; avoid sharing sensitive output.

## Routes

```bash
hyper agents routes list docs-demo
hyper agents routes add docs-demo web --port 3000
hyper agents routes add docs-demo public --port 8080 --no-auth --prefix app
hyper agents routes remove docs-demo web
```

Named updates preserve other routes. Authentication is enabled by default.
`--prefix` and `--root` are mutually exclusive. Desired route configuration
and resolved `route_statuses` are separate response fields.

The base OpenClaw launch has no public route. Desktop access requires explicit
environment and route configuration; see [remote desktop](/agents/remote-desktop).

## Stop, archive, restore, and delete

```bash
hyper agents stop docs-demo --yes
hyper agents wait docs-demo --state STOPPED
hyper agents archive docs-demo
hyper agents wait docs-demo --state ARCHIVED
hyper agents restore docs-demo
hyper agents wait docs-demo --state STOPPED
hyper agents start docs-demo
```

Archive and restore do not start the runtime. Lifecycle responses acknowledge
accepted operations; use wait to confirm the resulting state.

```bash
hyper agents stop docs-demo --yes
hyper agents wait docs-demo --state STOPPED
hyper agents delete docs-demo --yes
```

Delete is distinct from stop and accepts a durable soft deletion; acceptance
does not prove background cleanup has completed.

## Other commands

- `hyper agents activate <code> [--extend-existing]` redeems an activation code.
- `hyper agents routines` manages scheduled prompts; see [routines](/cli/commands/routines).
- `hyper websearch "release notes" --count 5` searches through the platform proxy.
- `hyper agents token <id>` refreshes agent access credentials.

The legacy Python CLI has additional and differently named options. In
particular, its `--force`, `--desktop`, `--wait` on stop, `budget`, and
`web-search` examples are not the TypeScript CLI interface.

The legacy Python CLI also accepts `hyper agents ls` as an alias for
`hyper agents list`. Its `hyper agents metrics <id> [--json]` command reads one
live Reef CPU and memory sample through the Backend WebSocket.
