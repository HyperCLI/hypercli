## Interactive Setup

```bash
hyper configure
```

This writes `$HYPER_HOME/config`, or `~/.hypercli/config` when `HYPER_HOME` is
unset. References to the default config path below use this active location.

## Verification Commands

`hyper me` calls the authenticated product `/api/auth/me` endpoint and then
attempts to add the current agent entitlement summary:

```bash
hyper me
hyper me --output json
```

Use it to verify identity and key capabilities before a billed operation. Its
output contains account identifiers and should not be pasted into public logs.

`hyper status` queries compact model and cluster health through the agents API:

```bash
hyper status
hyper status --output json
```

It is a health check, not an identity check. A successful `status` does not
replace `me` when diagnosing which account a product credential resolves to.

## Environment Variables

| Variable | Description |
| --- | --- |
| `HYPER_API_KEY` | Main HyperCLI API key |
| `HYPER_API_BASE` | Customer product/inference base URL |
| `HYPER_AGENTS_API_BASE` | Independent direct Agent-control base; never selects inference |
| `HYPER_AGENTS_API_KEY` | Platform runtime key; final credential fallback after all canonical key sources |
| `HYPERCLI_WALLET_PASSPHRASE` | Skip wallet passphrase prompts |

## URL Model

The CLI separates product/inference (`HYPER_API_BASE`) from direct Agent control
(`HYPER_AGENTS_API_BASE`):

- `HYPER_API_BASE`
  - billing
  - jobs
  - keys
  - account APIs
- product WebSocket base
  - derived from `HYPER_API_BASE` by scheme swap
- agents REST base
  - uses `HYPER_AGENTS_API_BASE` when supplied; otherwise derives from `HYPER_API_BASE`
  - create/start/stop/delete
  - files
  - exec
  - desktop token APIs
- agents WebSocket base
  - derived from the agents REST base
  - `/logs/{agent_id}`
  - `/shell/{agent_id}`

Recommended production value:

```bash
HYPER_API_BASE=https://api.hypercli.com
```

Recommended dev value:

```bash
HYPER_API_BASE=https://api.dev.hypercli.com
```

With no Agents base supplied, production derives `https://api.hypercli.com/agents` as the agents REST base
and `wss://api.agents.hypercli.com/ws` as the agents WebSocket base; dev
derives the `api.dev.hypercli.com` and `api.agents.dev.hypercli.com`
equivalents. A custom `HYPER_API_BASE` keeps its origin and gains an `/agents`
path suffix for the agents REST base.

Public TS, Python, and ACP CLIs do not support `--dev` or `--prod`; these flags
are reserved for admin tooling. Use `HYPER_API_BASE` and, independently,
`HYPER_AGENTS_API_BASE` in environment/config. Independent workspace, routine,
runner, and integration base overrides remain unsupported.

Each base reads environment before canonical config. With no Agents base in
either source, derive it from the product base. Changing the product base does
not replace an explicitly configured Agents base; when switching both to dev,
set the Agents base to `https://api.agents.dev.hypercli.com` as well.

## Shared Config File

Location:

```text
~/.hypercli/config
```

Example:

```bash
HYPER_API_KEY=hyper_...
HYPER_API_BASE=https://api.hypercli.com
```

## Local State Files

The CLI stores additional state in `~/.hypercli/`:

- `config`: shared API key and base URL
- `agent-key.json`: saved HyperCLI key from `hyper agent subscribe` or `hyper agent login`
- `agent-keys.yaml`: key history written by `hyper agent subscribe`
- `agent-jwt.json`: wallet-auth JWT used during agent login flows
- `agents.json`: cached agent metadata for ID prefix resolution
- `wallet.json`: local wallet file, either an encrypted keystore or a plaintext private-key wallet

## Priority Rules

The shared credential and endpoint settings are `HYPER_API_KEY`,
`HYPER_AGENTS_API_KEY`, `HYPER_API_BASE`, and `HYPER_AGENTS_API_BASE`. The retired names
`HYPERCLI_API_KEY`, `HYPERCLI_API_URL`, `HYPERCLI_WS_URL`, `AGENTS_API_BASE_URL`, and
`AGENTS_WS_URL` are not read; `hyper configure` (and the SDK `configure()` /
`saveCliConfig()` helpers) prunes them from `~/.hypercli/config` on write.

Shared SDK/CLI credentials resolve in this exact order:

1. an explicit command `--key` or SDK `api_key` argument, where supported
2. `HYPER_API_KEY` in the environment
3. `HYPER_API_KEY` in the active canonical config file
4. `HYPER_AGENTS_API_KEY` in the environment

Remove or update the higher-priority value when replacing a credential; writing
a new lower-priority value will not change the active key.

The Python voice, embedding, and model commands use canonical configuration.
Endpoint override flags such as `--base-url` are unsupported. Legacy login
state files are not additional shared-client credential sources.

Runner and Lagoon inject consistent defaults for `HYPER_API_BASE`,
`HYPER_AGENTS_API_BASE`, the appropriate ACP URL, and `HYPER_AGENTS_API_KEY`.
Customer overrides of either base and canonical `HYPER_API_KEY` in launch `env` or `secrets` are
preserved. The canonical key wins over the default runtime key, including for
broader uses such as managing other agents. The launch owner's auth key is
never automatically forwarded.

Explicit `HYPER_ACP_WS_URL` wins; otherwise derive ACP from the Agents base,
falling back to the product base only when no Agents base is supplied. Images
must not bake in a production Agents base that selects the wrong plane. ACP
transport uses the separate platform runtime key. External inference URLs/keys
must not implicitly redirect platform callbacks or reconnects.

For external inference in a managed runtime, set `HYPER_API_BASE` to
`https://inference.example.com` and supply that provider's `HYPER_API_KEY` in
`env` or `secrets`; retain the injected platform Agents base and ACP URL. For
a standalone runtime, also set `HYPER_AGENTS_API_BASE` to the intended control
endpoint (for example `https://api.agents.hypercli.com` for production).

## Diagnosing 401 Errors

A `401` with a server detail such as `API key is inactive` is an authentication
failure, not a flow or prompt failure. Repeating the render request will not
repair it.

1. Confirm the CLI version and resolved product API base without printing a
   credential:

```bash
hyper --version
echo "HYPER_API_BASE=${HYPER_API_BASE:-https://api.hypercli.com (default)}"
```

2. Check which credential *names* are present. Do not print their values:

```bash
python - <<'PY'
import os
from pathlib import Path

names = ("HYPER_API_KEY", "HYPER_AGENTS_API_KEY")
print("environment:", [name for name in names if os.environ.get(name)])
config = Path(os.environ.get("HYPER_HOME", "").strip() or Path.home() / ".hypercli") / "config"
if config.exists():
    configured = {
        line.split("=", 1)[0].strip()
        for line in config.read_text().splitlines()
        if "=" in line and not line.lstrip().startswith("#")
    }
    print("config file:", [name for name in names if name in configured])
else:
    print("config file: absent")
PY
```

3. Test the product identity once:

```bash
hyper me --output json
```

Do not paste successful `me` JSON into a public thread; it contains account
identifiers. If the command fails, report the API base, the source variable or
file name, HTTP status, and server detail. Never report the credential itself.

4. Activate or replace the credential at its highest-priority source. Use
`hyper configure` for `~/.hypercli/config`; update or unset an environment
variable when it is the active source. Run `hyper me` once more before retrying
the original operation.

Do not switch to a wallet, another account, dev, or `--x402` as an automatic
fallback. Besides changing billing identity, local flow inputs still require a
normal product-authenticated upload.
